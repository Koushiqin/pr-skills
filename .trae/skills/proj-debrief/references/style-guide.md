# 表达风格基准

用途：统一解释与话术的口吻。用户反馈"太抽象""不像人话"时对照本文件修正。

## 解释顺序（硬规则）

做什么 → 为什么 → 术语。不先抛术语再解释。

## 人话 ↔ 术语对照（示例，持续补充）

| 术语 | 人话 |
|---|---|
| 幂等 | 同一个操作执行多次，结果和执行一次一样 |
| 熔断 | 下游一直失败就先不调用它，直接返回兜底结果，等它恢复 |
| 上下文窗口 | 模型一次能"看见"的文字总量，超出的部分它记不住 |
| 向量召回 | 把问题和文档都变成一串数字，找数字最接近的文档 |

## 禁用表达

- 无证据时：大概是 / 应该是 / 一般来说 / 感觉上
- 无数据时：大幅提升 / 显著优化 / 性能提升 X%
- 书面腔：综上所述 / 由此可见 / 值得一提的是

## 话术句式（推荐骨架）

- 场景 + 做法 + 原因："我们在 X 场景里用了 Y，因为 Z"
- 问题 + 定位 + 解决："当时遇到 X，先通过 Y 定位到 Z，最后用 W 解决"
- 取舍 + 条件："选 A 不选 B 是因为 C；如果 D 变了，我会重新考虑 B"
